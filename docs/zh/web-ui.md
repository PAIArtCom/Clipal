# Web UI 使用说明

## 访问方式

启动 Clipal 后，在浏览器打开：

```text
http://127.0.0.1:3333/
```

如果你修改了端口，请把地址中的 `3333` 换成你的实际端口。

当前所在分区和客户端会记录在 URL 的 hash 中（例如 `#/providers/openai`、`#/status`），刷新页面或收藏后可回到同一视图。

## Web UI 能做什么

### Providers

- 按客户端分组查看 provider
- 新增、编辑、删除 API-key provider
- 启用或禁用 provider
- 调整 `auto` / `manual` 模式
- 在 `manual` 模式下固定某个 provider
- 录入单个 `api_key` 或多行 `api_keys`
- 配置 provider 级代理模式和自定义代理 URL
- 配置 provider 级模型覆盖
- 配置 provider 级 OpenAI `reasoning_effort` 或 Claude `thinking_budget_tokens`
- 对支持的客户端 / 服务组合发起 OAuth 授权
- 在 Add Provider 对话框里导入 OAuth 授权文件。当前支持 Codex CLI 的 `auth.json`（`~/.codex/auth.json`）、CLIProxyAPI 单账号 OAuth JSON，以及 sub2api 导出的 JSON；Clipal 只会导入与当前所选服务匹配的账号。
- 对 Claude 和 Codex OAuth 请求默认使用 Agent SDK 兼容上游包装，并由 Clipal 处理必要传输字段。
- 在 provider 详情中查看 OAuth 鉴权状态和最近刷新摘要
- 为 Codex、Claude 和 Google 账号（Antigravity）加载套餐和限额详情
- 在 provider 行内直接查看运行态：使用中、待命、已停用、冷却中（含剩余时间）、不可用、恢复探测中

### Global Settings

- 修改监听地址和端口
- 分别开启远程代理访问或远程 Web UI 访问；两者默认均关闭
- 修改日志级别
- 配置自动恢复、超时、请求体限制
- 配置熔断器
- 配置日志目录、保留天数、stdout 输出
- 配置桌面通知
- 有未保存的修改时会给出标记，离开页面前会询问是否放弃
- 仅在重启后生效的字段（监听地址、端口）带有琥珀色重启图标；其他字段说明收在标签旁的 ⓘ 图标中
- 开启远程 Web UI 访问时，保存前会要求确认，因为管理界面没有内置认证

### System Status

- 查看版本和运行时长
- 查看配置目录
- 查看各客户端当前模式、固定 provider、当前优先 provider
- 查看每个客户端最近一次切换和最近一次请求，带状态颜色和相对时间
- 查看每个 provider 的运行态、已配置 key 数、可用 key 数

### Services

- 调用 `clipal service` 的常见能力
- 安装、启动、停止、重启、卸载后台服务
- 查看后台服务状态

### CLI Takeover

- 在 UI 中查看当前支持的一键接管项
- 一键接管 `Claude Code`、`Codex CLI`、`OpenCode`、`Antigravity CLI`、`Continue`、`Aider` 和 `Goose` 的用户级配置
- 首次接管前自动创建备份，便于后续回滚
- 一键回滚到接管前捕获的原始文件状态
- 展示 Clipal 实际管理的目标配置文件路径
- 在 apply 前预览“当前文件”和“Apply 后将写入的结果”

Codex CLI、Claude Code 与 Antigravity CLI 共用接管周期。首次 apply 捕获全部管理文件的内容、原始存在状态和权限；重复 apply 或修改入口地址时保留该基线。所有文件先验证并暂存，再替换目标；写入失败会恢复到本次操作前的状态。Rollback 恢复本周期基线并结束周期，下一次 apply 重新捕获基线。历史备份归档保留在磁盘上；若自动恢复本身失败，活动备份会保留供重试。这是可恢复的多文件操作，不承诺跨文件在断电时整体原子提交。

“**配置位置**”允许指定绝对客户端目录，以及 Codex 的可选 profile。目录留空时读取 `CODEX_HOME` / `CLAUDE_CONFIG_DIR`，再回退到客户端默认值。选择 Codex profile 后，管理 `<profile>.config.toml`，运行时应使用匹配的 `CODEX_HOME` 和 `codex --profile <profile>`。Claude 默认使用 `~/.claude.json` 保存 onboarding，自定义目录时使用 `<CLAUDE_CONFIG_DIR>/.claude.json`。Antigravity 保留官方固定的设置文件位置，允许选择 shell 类型和启动文件目录。后台服务无法检测 `SHELL` 时，需显式选择 bash、zsh 或 sh。修改位置前必须先回滚活动周期。

“**配置已写入**”仅确认文件内容，运行时请求仍为“**尚未验证**”。Claude 的其他提供商选择变量和 host-managed 环境冲突会明确提示；项目或受管设置、Codex profile 仍可能覆盖用户默认值。Clipal 不清除企业策略。后台服务与启动客户端的终端可能继承不同环境，必要时请显式选择配置位置。

Antigravity 管理 `.bashrc` 及首个适用的 Bash 登录文件（`.bash_profile`、`.bash_login` 或 `.profile`）；Zsh 使用 `$ZDOTDIR/.zshrc`，未设置时使用 HOME；POSIX sh 使用 `.profile`。显式选择 shell 目录时以其为准。全部文件均纳入预览与备份。Apply 和 Rollback 后都应新开终端：仅 source 恢复后的配置不会清除当前 shell 已经导出的变量。

管理 API：`POST /api/integrations/<product>/target` 接受 `{ "config_dir": "/absolute/path", "profile": "work", "shell_dir": "", "shell": "" }`；`profile` 仅适用于 Codex，`shell_dir` / `shell` 仅适用于 Antigravity（`shell` 接受 bash、zsh 或 sh），Antigravity 不接受自定义 `config_dir`。列表及操作响应包含 `target_options` 和 `verification`（`not_verified` 或 `blocked`）。某个客户端文件损坏时，只在对应卡片报错，其他客户端及可用回滚操作仍可访问。


实际客户端验证可使用隔离的 smoke 脚本：先启动已配置可用账号的网关，再构建并执行以下命令。脚本会发起真实模型请求，检查回滚和第二轮接管，保持用户原有客户端文件不变。仅选择具有可用上游账号的客户端；省略 `--products` 会同时验证 Claude。

```sh
go build -o /tmp/clipal-takeover ./cmd/clipal
python3 scripts/cli_takeover_smoke.py --binary /tmp/clipal-takeover --products codex,antigravity
```

- `OpenCode` 的一键接管会新增或更新 `provider.clipal`，并把当前 `model` 改写为 `clipal/<当前模型ID>`
- `Continue` 的一键接管会新增或更新用户级 `Clipal` 模型项
- `Aider` 的一键接管会更新 home 级 `openai-api-base`，并补一个最小 OpenAI 兼容 `model`；已有 `openai-api-key` 会保留，只有缺失时才自动补占位值 `clipal`
- `Goose` 的一键接管会管理 `~/.config/goose/custom_providers/` 下的独立 custom provider 文件

### 导出完整备份

- 在“备份与导入”页签的“导出完整备份”面板中下载完整的 `clipal.data/v1` JSON 备份
- 备份包含全局与客户端配置、Provider API Key、OAuth access 和 refresh token，以及用量历史

### 导入数据

- 在“备份与导入”页签的“导入数据”面板中预览并执行原生备份或受支持的外部凭据导入

## 状态页里常见的 provider 状态

- `disabled`：配置里手动禁用了
- `unavailable`：当前因为鉴权、计费、额度问题，或没有可用 API Key 而不可用
- `cooling_down`：因为可恢复错误或熔断打开而处于冷却期
- `recovery_probe`：Clipal 正在用有限流量探测这个 provider 是否已经恢复

## 安全边界

- Web UI 默认只允许本机访问
- 如用户在全局设置明确开启 `allow_remote_web_ui`，管理界面可远程访问；此模式没有内置认证，请使用防火墙、VPN 或反向代理保护
- 管理 API 设计为本机使用，不提供独立认证层
- 变更类 API 请求要求 `X-Clipal-UI: 1`
- 带请求体的变更类 API 需要 `Content-Type: application/json`
- UI 不会直接展示每个 API Key 的明文

## 哪些修改通常立即生效

大多数配置变更会被热加载，无需重启，例如：

- provider 列表
- 优先级
- `mode`
- 失败切换相关参数
- 请求体限制
- 通知配置

通常需要重启才能完全生效的项目：

- 监听地址
- 监听端口
- 某些日志输出目标相关设置

## OAuth 账号请求环境

添加新 OAuth 账号时提供“**请求国家 / 地区**”和“**请求时区（IANA）**”下拉框，预填 **US / `America/New_York`**。它们是请求配置，不能证明账号注册地或账单国家。纽约的 IANA 时区自动处理夏令时，不保存固定 UTC−5 偏移。未修改的默认值保存 `source: default`，修改后的选择保存 `source: user`。新增 OAuth 与账号环境对话框共用国家和时区选项。国家名随界面语言显示，时区保留 IANA 标识。原生下拉框支持键盘导航和按名称定位。切换国家不会自动改写时区，已保存的时区别名仍可选择。

配置绑定 OAuth 账号，同一账号关联的 provider 共享设置。刷新、重新授权、重启和切换代理均保留已有配置。导入保留原值及来源，不应用新账号默认值。没有可信来源的旧值保留显示，并标记 `needs_confirmation: true`；它们可能来自出口估算，用户需要在账号地球按钮中检查、修改并明确保存。确认前，地区字段不应用到请求元数据。读取、导入预览和导出不会写回迁移。凭据中的上游地区属性单独记录和展示，不覆盖请求配置。

设备标识由版本命名空间、OAuth 服务及账号 ID 做 SHA-256 生成。缺少账号 ID 时使用稳定账号身份或 ref，诊断会说明。仅含 token 的旧账号也可通过该回退身份确认请求配置，不改变 provider 的账号关联身份。已确认的账号语言用于 `Accept-Language`，支持的环境头及适配器元数据使用账号配置；用户消息、工具和会话 ID 保持原有含义。Claude metadata 修改后重新签名 billing hash；故障切换采用当前所选账号的配置。

代理来源遵循 provider 配置、继承的全局配置、环境策略及 `NO_PROXY`。Clipal 实现 HTTP CONNECT、HTTPS 代理和 SOCKS5，所有代理请求保留目标域名，由代理解析和分流。VMess/VLESS 等由代理软件处理。Clipal 不探测专用控制器，不自动发现或接管代理监听端口。TUN 对 Clipal 透明，未指定代理入口不能证明实际为物理直连。

账号 DNS 默认 **auto**，按每个目标的 provider、全局、环境／系统代理策略及 `NO_PROXY` 选择路径。有标准代理时保留目标域名，由代理解析，不依赖公共 DoH。无代理入口时，auto 优先尝试 **Cloudflare → Google DoH** 及返回的目标 IP；解析、TCP 或标准 TLS 连接建立失败后，回退系统域名通路。DoH 阶段最多五秒，较短的请求期限也会为回退预留时间。两条路径上的 VPN／TUN 均交给操作系统路由。标准 HTTPS 在发送任何 HTTP 请求数据前完成路径切换和 TLS 校验，不重放业务请求。Clipal 不扫描代理控制器或端口，不修改系统网络配置、保存的 DNS 选择或账号地区。显式 `cloudflare`／`google` 仍要求指定 DoH 服务解析目标，失败不回退系统目标 DNS；`system` 沿用系统解析器。DoH 服务域名使用系统引导解析并保留固定 IP 后备，两条路径均保留原始 TLS SNI 和证书校验。IPv4／IPv6 目标连接以 250 毫秒间隔竞速并共享请求期限。代理连接失败不回退直连目标；无显式代理也不能证明物理直连，因为 TUN 仍可能生效。第一跳代理自身为域名时可能需要系统解析。有标准代理时，无论保存哪个 DNS 值都由代理解析，不启用严格代理预检。

业务请求复用账号 HTTP 客户端和连接池；仅在新建连接需要尚未缓存的地址时查询 DoH。成功结果从各条 DNS 响应收到时起按 TTL 计时，合并 A／AAAA 结果取最早到期时间，最长五分钟；同一账号、路由和域名的并发冷查询合并为一次查询流程。解析失败后退避五秒，到期重新尝试 DoH；auto 在退避期间可走系统域名通路，显式指定 DoH 时仍严格失败。完整五秒自动 DNS 解析预算耗尽也会建立退避；目标 TCP／TLS 连接错误不会成为 DNS 失败缓存。请求取消或调用方的较短期限不会建立退避，等待者可独立取消。成功与失败条目合计最多 256 个，优先淘汰最早到期的条目。缓存内容为 DNS 结果，不缓存模型响应。

“**检查一致性**”报告所选代理入口、由谁解析目标域名，以及不携带凭据的目标 HTTP 连接是否完成。收到 HTTP 状态只能证明 HTTP 连通性，不能证明 OAuth 认证。IP 参考服务可能报告自己的出口 IP、国家和时区；即使代理入口相同，也不能证明模型目标使用相同出口，因此目标出口保持“**尚未核验**”。观测不会初始化或修改账号地区。诊断不发送账号凭据、token 刷新或付费模型请求。用量元数据的总时间预算为 30 秒，包含自动连接选择、刷新及上游请求。

“**代理下附加公共 DoH 参考诊断**”默认不勾选，仅对当前诊断请求生效。有标准代理时，在连通性检查之后，通过同一入口查询保存的 Cloudflare／Google 选择；`auto`／`system` 使用 Cloudflare → Google。结果不能证明代理实际 DNS 后端、目标 IP 或出口。失败单独显示为“**尚未核验**”，不阻断业务请求，不提供严格预检选项。参考查询最多占用 10 秒，受诊断总计 25 秒的期限约束，不携带账号凭据或环境请求头。

管理接口为 `GET` / `PUT /api/providers/<client>/<name>/oauth-environment` 和 `POST /api/providers/<client>/<name>/oauth-diagnostics`。POST 可使用空请求体或 `{ "check_doh": false }`；`{ "check_doh": true }` 开启代理参考查询。无显式代理时忽略此选项，常规检查使用账号实际 DNS 策略。GET 和诊断不改变配置；PUT 明确确认或修改国家及 IANA 时区，核验已加载账号身份，保留 DNS 和 token，沿用 localhost 管理访问与 CSRF 控制。


## Provider 列表

Google 渠道支持 Gemini API Key provider 和 Antigravity OAuth 账号。渠道主标识为 `google`（`google.yaml`、`/api/providers/google`、`#/providers/google`）。管理 API 和页面链接中的 `gemini` 保留为兼容别名；模型名称和 Gemini 兼容协议字段沿用上游规范。状态与 OAuth 响应使用 `google`。

Claude / OpenAI / Google 标签位于一个面板的上边缘，面板内的内容都属于当前选中的客户端。面板第一行是该客户端的路由：Auto / Manual 切换（ⓘ 说明模式含义）和以靶心图标标示的当前路由候选，右侧为“添加 Provider”；分组内 Provider 超过 8 个时，这一行还会出现搜索框（按名称或 Base URL）。

这一行下方分为左右两栏。左栏按优先级一行一个列出 Provider：拖拽手柄（提示中含配置优先级）、名称、运行态（使用中、待命、已停用、冷却中含剩余时间、不可用、恢复探测中）和启用开关。点击某行，或聚焦名称后按回车，即在右栏显示该 Provider；未选择时显示第一个。

右栏详情显示名称、运行态、OAuth 标记及上游主机或 Provider ID，右上角为固定、编辑（OAuth 账号改为打开账号环境）和删除。其下依次为：异常原因；固定三列的关键数据——鉴权状态与最近刷新时间（OAuth）或 Key 数量（API Key）、Token 用量及输入/输出、今日与近 7 天花费，尚无数据时显示短横线；OAuth 套餐与额度及用量进度条；Base URL、代理和 Provider ID 列表行，可一键复制。悬停或聚焦用量、花费可查看精确金额和 Token 细分。

“套餐与限额”中点击“加载”读取账号的上游订阅与额度，之后可点击“刷新”。Google 额度按上游返回的模型或额度分组显示已用比例，有重置时间时一并显示；剩余额度为 100% 时显示已用 0%。Antigravity 的额度接口为空或不受支持时，改读模型目录中明确返回的额度字段，没有额度值的模型不生成进度条。账号初始化或授权失败会显示错误。上游未返回额度时明确提示，刷新失败则显示错误并保留上次数据。

桌面端滚动页面时，右栏详情吸附在顶部导航下方。详情过长时正文在卡片内滚动，名称与操作按钮保持可见。切换 Provider 后新详情从顶部显示，列表位置保持不变。用量和花费的提示浮层在悬停或键盘聚焦时显示，不受正文滚动区域裁切。窄屏和低窗口的详情使用普通页面滚动。

拖动手柄调整顺序，或聚焦手柄后按 Alt+↑ / Alt+↓。搜索期间暂停排序，因为此时可见的只是部分列表。排序保存失败会恢复原顺序。

宽度不超过 760px 或高度不超过 360px 的窗口中，列表与详情轮流显示：选择 Provider 后详情取代列表，点击“返回”回到列表。搜索无匹配项时显示列表的空结果提示，清空搜索后恢复选中项的详情。当前候选表示路由偏好，不代表已观察到成功请求。

自动模式可能沿用正在成功的 Provider 或跳过不可用候选，配置顺序不代表每次请求的实际顺序。

CLI 接管卡片展示目标配置路径（主目录下以 `~` 缩写，完整路径见悬停提示）、警告图标（悬停查看工具专属注意事项）、恢复图标按钮，以及默认收起的变更预览，展开按钮上显示新增和移除行数。展开预览后该卡片占满整行。已接管且有备份时，预览对比回滚备份；否则对比接管后的计划结果。完整的当前文件与目标文件位于下一层。文件过大无法逐行对比时只提供完整文件视图。

## 保存、草稿与连接反馈

切换模式或固定 Provider 时，在服务器确认保存成功前保留原选择。Provider 保存、删除、启用开关、模式切换和固定操作会锁定冲突的列表操作及客户端切换，直到请求和刷新完成；保存失败会保留原状态并显示错误，可重新执行操作。

关闭有修改的 Provider 或 OAuth 账号环境表单时（包括 Escape 和点击遮罩），会先询问是否丢弃。保存失败保留输入。全局设置加载或重置期间会禁用表单及保存、重置按钮，避免迟到的读取结果覆盖新修改。读取失败时会显示可重试的页内提示；首次加载成功前表单保持禁用，重置失败则保留当前草稿。刷新或关闭浏览器也会提醒未保存的设置及表单修改。草稿仅保存在内存中，确认丢弃或离开页面后不会保留。

损坏的 JSON 会在导入格式识别前被拒绝，错误中会标出文件名。导入文件读取、预览和执行期间会锁定文件与模式选择，并阻止重复提交。执行导入及刷新期间不能关闭预览或切换页签；失败后恢复操作。

Providers 或系统状态页可见时每 3 秒刷新网关状态；“服务”或系统状态页可见时刷新服务状态。状态请求失败后在这些页面显示持续横幅，不反复弹出错误消息。保留上次成功的数据，并注明更新时间；从未成功获取时明确提示。超过 15 秒未更新的数据标记为过期。请求在 10 秒后超时，不重叠发送轮询；可点击重试，成功刷新后横幅自动消除。状态刷新失败本身不代表上游模型请求已经失败。

## 表单控件与操作反馈

超时和路由时长使用数值与单位选择器，请求体大小可选择字节、KiB、MiB 或 GiB。可选路由时长留空时使用默认值。请求体大小至少为 64 MiB；空闲和响应头超时设为零时关闭，否则至少为 5 分钟，低于限制的值会在提交前提示。已有复合时长和细粒度数值在明确编辑前保留原值，打开表单不会自动规范化配置。路由和熔断功能关闭时，对应参数控件停用，但保留配置值。

思考强度提供常用值建议，也允许模型专属值；留空表示不覆盖。Provider 名称在提交前校验，点击可见字段标签可聚焦对应控件。客户端标签支持左右方向键切换。触屏设备上的操作按钮提供更大的点击区域。

弹窗打开后自动聚焦，Tab 和 Shift+Tab 在弹窗内循环，背景不可交互，关闭后焦点回到打开入口。账号环境加载和诊断期间可关闭弹窗，迟到的结果不会修改已关闭的对话框。账号配置加载失败可在弹窗内重试。账号配置保存时显示忙碌状态，成功后显示通知；已关闭的加载或诊断操作不会弹出迟到的错误。

Provider 列表加载失败时保留上次数据并显示重试提示，不会误报为空分组；重新加载成功前暂时停用变更操作。服务 HTTP 错误会显示失败，连接中断时明确标记操作结果尚未确认并继续检查状态。
