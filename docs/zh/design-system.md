# Clipal 落地页设计规范

## 双语共用结构，中文独立表达

中英文使用同一套页面结构、组件、资源和交互逻辑。中文文案按开发者的阅读习惯独立写作，不逐句对译；产品能力、使用边界、命令、入口和演示状态必须一致。

英文使用 EB Garamond 正体与斜体建立标题层次。中文采用宋体标题，以正体和强调色区分重点，不强行模仿拉丁斜体；正文与操作界面使用系统中文无衬线字体。品牌名和既有标志保持 Clipal，文字标识中的绿色句点为装饰。

## 视觉系统

- 底色 `#0a0a0a`，纸白 `#f1f0ea`，强调绿 `#c8ff3d`，次要文字 `#a3a39b`。
- 429 使用橙色 `#ff5a1f`，冷却使用琥珀色 `#d8b077`，可用与成功状态使用强调绿。状态始终带文字，不能仅靠颜色识别。
- 保留宽屏网格、错位大标题、章节编号、黑／纸白／绿色区块和水平分隔。文字内容要控制行长，不通过压缩行距来适配手机。
- 中文 Hero 标题使用 `clamp(42px,8.4vw,144px)`，章节标题使用 `clamp(32px,4.7vw,76px)`，使用宋体系统回退与适合中文的行高。
- 桌面维持大尺度字标，手机同比收敛；完整显示 `Clipal.`，不裁切字母轮廓。

## 内容组织

1. 首屏说明本地网关的用途，提供安装、查看控制台和 npm 复制入口。
2. 客户端跑马灯用于展示生态；完整的 18 项接管目录仍单独保留。
3. 四个真实控制台视图：提供商、CLI 接管、用量、设置。截图标注为示例配置，可放大并打开原图。
4. 功能区讲清预览／应用／回滚、自动故障转移、原生协议、OAuth 和费用来源。
5. 安装区保留 npm、macOS/Linux、Windows 三种渠道，以及前台启动、后台服务、本地控制台与中文 AI 安装提示词。
6. FAQ 解释本地与上游的边界、凭证存储、回滚范围、协议和费用。
7. 社区入口、原始微信二维码、收尾安装操作和页尾字标。

## Hero 的三个故事

同一客户端、同一渠道依次展示三段故事，播完再轮换客户端：

- 正常路由：API 提供商直接成功，不出现 429。
- 提供商兜底：API 已无可用密钥时出现 429，进入冷却，改用兼容的 OAuth 提供商。
- 黏性路由：后续匹配请求复用已成功的提供商，减少不必要的切换。

API 与 OAuth 提供商分别显示认证类型、渠道、账号来源和状态。Claude、OpenAI、Google 渠道对应的 OAuth 账号标签为 Claude、Codex、Antigravity。

429 后 API 提供商在后续兜底和黏性段持续显示“冷却中”；只有新一轮示例才重置。不显示虚构的倒计时，不暗示所有请求永久固定，也不暗示协议自动互转。所有数据均为示意，不连接实际网关或上游。

播放控件保持次要；离屏和后台停播，减少动态效果时默认暂停。

## 手机与可访问性

- Hero 的两个按钮始终同排，通过控件字号和内边距适配，保留正常正文间距。
- 640px 以下客户端目录使用紧凑双列，行高至少 64px，移除装饰编号。
- 纵向布局切换到单列 Grid，不保留桌面的十二列间隙。安装列显式使用 `minmax(0,1fr)`，子项允许收缩。
- 长命令在代码框内滚动，完整文本和复制内容保持一致。不能通过页面裁切隐藏溢出。
- 标签页支持方向键、Home、End。截图弹窗支持 Escape，关闭后归还焦点。
- 复制按钮有成功／失败提示，失败时选择原文以便手动复制；界面标签与动态状态由 HTML 提供中文文案。
- FAQ、后台服务、AI 提示词和社区二维码采用原生 details/summary。无 JavaScript 时主要内容仍可读。

## 产品边界

本地管理不等于离线推理；请求及必要认证信息会发给选定上游。保留 Anthropic、OpenAI、Gemini 原生协议，不承诺任意协议转换。自动模式先尝试可用密钥，再切换提供商；手动模式保持固定。

配置接管保留受管理文件的基线和回滚能力，不宣称通用无损 AST 或跨文件断电原子事务。API Key 提供商使用 YAML，OAuth 凭证位于独立目录，不承诺所有凭证均加密。

费用优先使用上游报告，否则使用目录中的精确模型价格；未知价格保持缺失。目录估算不等于实际账单，不虚构延迟、内存或可用率指标。
