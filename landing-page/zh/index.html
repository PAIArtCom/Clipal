ZERO-TRUST SECURITY ARCHITECTURE

安全承诺与常见问题解答

面向严苛工程师的透明架构说明。

我的 API Key 和 OAuth 凭据会被上传到云端吗？

绝对不会。Clipal 是一款 100% 的本地独立可执行程序。所有的 Key、Token 及会话配置均加密持久化在本地 config.json 中，零数据外流，无任何第三方云端遥测（Zero Telemetry）。源代码完全开放于 GitHub 接受全球开发者审计。

为什么接管我的 CLI 配置不会造成破坏？

区别于粗暴的覆盖写入，Clipal 针对每一款 CLI 工具都建立了严格的配置契约。通过 JSON / YAML / TOML 的 AST 语法树合并，仅写入 Clipal 必须的 Base URL 等映射字段。接管前强制捕获文件基线，任何时刻点击 Rollback 即可 100% 字节级还原。

Clipal 如何解决网络污染与握手超时报错？

Clipal 原生实现代理继承与分级 DoH 解析。在存在标准系统代理时直接保留域名移交代理；在直连环境下默认优先使用 Cloudflare 与 Google 的 DNS-over-HTTPS (DoH) 安全解析，失败时无缝降级回退系统 DNS，从底层消灭握手断连与污染问题。

什么是统一路由 /clipal？我还需要配置旧的 /claudecode 吗？

自 v0.25+ 起，Clipal 已实现智能协议嗅探。你只需将所有客户端的 Base URL 统一指向 http://127.0.0.1:3333/clipal，网关会自动辨识 Anthropic、OpenAI 或 Gemini 协议并分发。旧别名仅为向下兼容历史客户端保留。

npm 12+ 提示安装脚本被拦截，该如何处理？

自 v0.31 起，Clipal npm 包已全面采用平台可选依赖（Optional Dependencies）直接分发各系统二进制，不再使用 postinstall 安装脚本。因此在 npm 12+ 下直接执行 npm install -g clipal 即可顺畅安装，无需附加 --allow-scripts 参数。

在 Codex 中使用 Clipal 会导致会话历史丢失吗？

不会，反而更加稳定。针对 Codex / OpenCode，Clipal 采用标准化的 model_provider = 'clipal'。不同于频繁更换 Provider 标识会导致会话重置的做法，Clipal 保持 Provider 标识永久一致，仅在内部调度 Key 或端点，从而完整保全历史会话上下文。
