AI 编程工具一个本地网关

工具照常用，连接交给 Clipal。

    自动故障转移

    主路线受限，还有备用路线。

    自动模式先尝试同一提供商的下一个可用密钥，再切换到其他提供商。需要固定路线时，可在手动模式下指定提供商。

    流程示意
    提供商 A
    key_01已选中
    key_02备用
    提供商 B
    key_01备用

    01 / 从当前提供商和密钥开始。

    02 / 必要时尝试该提供商的下一个可用密钥。

    03 / 再尝试其他兼容提供商。

    手动模式保持固定，不会自动切换密钥或提供商。

    05常见问题

    本地运行，边界清楚。

    “本地”意味着 AI 请求不会离开电脑吗？ +

    不是。Clipal 在本地运行网关和管理控制台，但会向你选择的上游提供商发送 API 请求及必要认证信息，不等于离线推理。管理界面仅接受本地回环连接，代理的监听范围可单独配置。

    配置和凭证保存在哪里？ +

    API Key 提供商保存在 ~/.clipal 下的 YAML 文件中，OAuth 凭证单独保存在 ~/.clipal/oauth/。请通过适当的本机文件权限保护它们；Clipal 不承诺所有已存储凭证均已加密。

    CLI 接管回滚会恢复什么？ +

    回滚会把受管理文件恢复为本轮接管最初保存的备份；重复应用仍保留同一份备份。项目、会话和环境设置仍可能覆盖工具的连接设置。修改 Shell 集成后，请打开新终端。

    Clipal 会转换不同模型的协议吗？ +

    Clipal 保留 Anthropic、OpenAI 和 Gemini 的原生请求格式，通过 /clipal/* 按请求路径路由。上游需要兼容工具发送的协议，不支持任意协议之间的自动转换。

    应该怎样理解费用数据？ +

    Clipal 优先采用上游报告的费用；若不可用，则使用内置价格目录中精确匹配模型的价格。未知价格保持缺失，目录更新不会重算历史费用。目录计算结果是估算值，不是账单保证。
