## v0.29.0

### English

#### Highlights

- OAuth request country and timezone use searchable, keyboard-navigable pickers. Timezone choices show their current UTC offset, and users choose from valid options instead of typing values manually.
- Refined dark and light theme coverage, tab selection animation, provider form focus styling, and spacing inside provider edit dialogs.
- Updated provider reasoning controls for OpenAI, Claude, and Gemini, with model-dependent options and an inherit-default choice.
- Codex OAuth providers now serve the Codex model catalog, allowing Codex CLI to discover account-available models through Clipal.

#### Codex Model Catalog

- Clipal supports both Codex-native `GET /models?client_version=...` and OpenAI-compatible `GET /v1/models` catalog requests on the proxied route.
- Catalog requests forward only the supported `client_version` parameter to the Codex upstream and return the protocol-appropriate response shape. Model discovery is no longer treated as an unavailable OpenAI provider request.

#### Provider Overrides

- OpenAI reasoning effort is a select control with `none`, `minimal`, `low`, `medium`, `high`, `xhigh`, and `max`. Model availability varies; Responses requests receive `reasoning.effort`, while Chat Completions only replace an existing `reasoning_effort` field.
- Claude uses adaptive thinking with `output_config.effort` (`low`, `medium`, `high`, `xhigh`, or `max`, depending on model). The fixed `thinking_budget_tokens` override has been removed. Replace `overrides.claude.thinking_budget_tokens` with `overrides.claude.effort`; older budget values are no longer applied.
- Gemini providers can set `thinking_level` (`minimal`, `low`, `medium`, or `high`, depending on model), which Clipal applies to `generationConfig.thinkingConfig.thinkingLevel` for `generateContent` requests.
- Provider override settings are available through the Web UI, management API, YAML configuration, and data transfer.

#### Verification

- Go 1.27.3 tests, builds, and six release-target cross-builds pass; the Web UI test suite passes.

### 中文

#### 亮点

- OAuth 请求地区和时区改为可搜索、支持键盘定位的选项列表。时区显示当前 UTC 偏移，用户从有效选项中选择，无需手动输入。
- 完善深色／浅色主题覆盖，增加标签切换滑动动效，并调整 Provider 编辑窗口的焦点样式与内容间距。
- 更新 OpenAI、Claude 和 Gemini 的推理控制项，按模型提供档位并支持继承默认值。
- Codex OAuth Provider 现可提供 Codex 模型目录，Codex CLI 能够通过 Clipal 发现当前已认证账号可用的模型。

#### Codex 模型目录

- Clipal 同时支持代理路由上的 Codex 原生 `GET /models?client_version=...` 与 OpenAI 兼容的 `GET /v1/models` 模型目录请求。
- 目录请求只会将受支持的 `client_version` 参数转发到 Codex 上游，并返回相应协议要求的响应格式；模型发现不会再被当作不可用的 OpenAI Provider 请求。

#### Provider 覆盖项

- OpenAI reasoning effort 使用下拉选项：`none`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`。具体档位取决于模型；Responses 请求写入 `reasoning.effort`，Chat Completions 仅替换请求中已有的 `reasoning_effort`。
- Claude 使用 adaptive thinking 和 `output_config.effort`（`low`、`medium`、`high`、`xhigh` 或 `max`，具体取决于模型）。已移除固定 `thinking_budget_tokens` 覆盖。请将 `overrides.claude.thinking_budget_tokens` 改为 `overrides.claude.effort`；旧 budget 值不再生效。
- Gemini Provider 可设置 `thinking_level`（`minimal`、`low`、`medium` 或 `high`，具体取决于模型），Clipal 会在 `generateContent` 请求中写入 `generationConfig.thinkingConfig.thinkingLevel`。
- Provider 覆盖项可通过 Web UI、管理 API、YAML 配置和数据导入导出使用。

#### 验证

- Go 1.27.3 下的测试、构建和六个发布平台交叉编译均通过；Web UI 测试通过。
