## v0.25.0

### English

#### Highlights

- OAuth accounts now own stable device identities and editable request country/timezone preferences, shared across their linked providers.
- Standard proxies resolve target domains without a public DoH prerequisite. Routes without an explicit proxy use Cloudflare → Google DoH in automatic mode.
- Added account-environment management and provider consistency diagnostics to the Web UI.

#### What Changed

- New authorizations default to US / `America/New_York`, with `default` or `user` provenance. IANA timezones handle daylight saving; these preferences do not establish registration or billing country. Refresh, reauthorization, restart and proxy changes retain existing account choices.
- Device IDs derive from the OAuth service and account identity instead of conversations. Supported request headers and adapter metadata use the selected account's confirmed preferences; failover rebinds them and Claude metadata changes re-sign its billing hash.
- HTTP CONNECT, HTTPS proxies and SOCKS5 preserve target domains for proxy-owned resolution and routing. Provider, global, environment and `NO_PROXY` policies remain authoritative, including for the native Claude client. No proxy-software controller discovery or exit-based region inference is used.
- Automatic DNS uses Cloudflare → Google only without an explicit proxy. Saved DNS choices are preserved; proxy business requests never query public DoH. Optional proxy DoH reference diagnostics default off, report failure separately and cannot block refresh, usage or model requests.
- Diagnostics report the selected entry, DNS ownership and anonymous target reachability. Reference-service exits do not prove target egress; target exits and authentication remain unverified by this diagnostic.
- Native backups retain request preferences and provenance. Credential reads, exports and import previews do not persist migration. Legacy regions remain pending confirmation and are omitted from outgoing metadata until confirmed; token-only legacy accounts can also confirm their preferences. Imports never receive new-authorization defaults.
- Environment updates and token saves are serialized through the existing import barrier. Resolved-IP connections stagger IPv4/IPv6 attempts and share bounded retry budgets.
- Account-environment handling does not modify operating-system or Desktop settings.

#### Maintenance

- Updated the pinned Go toolchain to `1.26.9` and `golang.org/x/net` to `0.60.0` to include the standard-library and HTTP/2 security fixes required by the release scan.

### 中文

#### 亮点

- OAuth 账号独立保存稳定设备标识与可编辑的请求国家、时区，同一账号关联的 provider 共享配置。
- 标准代理负责解析目标域名，不依赖公共 DoH；自动模式在无显式代理时使用 Cloudflare → Google DoH。
- Web UI 新增账号环境管理和 provider 一致性诊断。

#### 变更内容

- 新授权默认 US / `America/New_York`，记录 `default` 或 `user` 来源。IANA 时区自动处理夏令时；这些请求配置不能证明注册地或账单国家。刷新、重新授权、重启和切换代理保留已有账号配置。
- 设备标识由 OAuth 服务与账号身份生成，不再随会话变化。支持的请求头和适配器元数据使用当前账号已确认的配置；故障切换重新绑定身份，Claude metadata 修改后重新签名 billing hash。
- HTTP CONNECT、HTTPS 代理和 SOCKS5 保留目标域名，由代理解析和分流。沿用 provider、全局、环境变量和 `NO_PROXY` 策略，Claude 原生客户端同样保留这些策略。不探测代理软件控制器，也不根据出口推断账号地区。
- 自动 DNS 仅在无显式代理时使用 Cloudflare → Google。已有 DNS 配置保持原值；代理业务请求不查询公共 DoH。代理下的可选 DoH 参考诊断默认关闭，失败单独显示，不阻断刷新、用量和模型请求。
- 诊断展示所选入口、域名解析归属及匿名目标连接结果。参考服务出口不能证明目标出口；该诊断不会核验目标出口或上游认证。
- 原生备份保留请求配置及来源。读取凭据、导出和导入预览不写入迁移结果。旧地区保持待确认，确认前不写入请求元数据；仅含 token 的旧账号也能确认配置。导入不应用新授权默认值。
- 环境更新与 token 保存通过现有导入锁协议串行处理。解析后连接采用 IPv4/IPv6 交错尝试，多地址重试共享有限预算。
- 账号环境处理不修改操作系统或 Desktop 设置。

#### 维护

- Go 工具链更新至 `1.26.9`，`golang.org/x/net` 更新至 `0.60.0`，包含发布扫描要求的标准库及 HTTP/2 安全修复。
