## v0.31.1

### English

#### CLI Client Takeover

- **Codex CLI**: Preserves existing user-managed provider options in `config.toml` under `[model_providers.clipal]` when applying or refreshing takeover, modifying only the fields owned by Clipal.
- **Goose**: Updates global `config.yaml` with `active_provider: clipal` and `providers.clipal.model` alongside `custom_providers/clipal.json`, so Goose sessions route through Clipal immediately.
- **Goose Pre-flight Check**: Blocks takeover if `GOOSE_PROVIDER` or `GOOSE_MODEL` environment variables are set, warning that environment variables override file configuration.
- **OpenCode v2**: Realigned takeover with OpenCode v2 configuration. Routes only enabled protocol endpoints (`openai` -> `/v1`, `anthropic` -> `/`, `google` -> `/`) without rewriting model catalogs or interfering with models.dev inventory.
- **OpenCode Policy & Shadowing**: Evaluates OpenCode wildcard policies (`action: "provider.use", effect: "deny"`) and rejects takeover when policy forbids a provider; detects configuration layer endpoint shadowing.
- **Legacy Route Detection**: Tightened legacy takeover URL detection to exact `/clipal` and `/clipal/v1` gateway paths, avoiding false positives on lookalike endpoints.

#### Standalone Installers

- **PowerShell (`install.ps1`)**: Resolves the latest release tag via HTTP redirect headers from `releases/latest` instead of the GitHub REST API, avoiding unauthenticated rate limits (HTTP 403) on shared network IPs.

#### Documentation

- Clarified Goose environment variable precedence and Grok configuration layer override behavior in takeover guidance.

#### Verification

- `go test ./...` passes.
- `./scripts/test_installers.sh` passes.
- `./scripts/test_npm_packaging.sh` passes.
- `make vuln` reports 0 vulnerabilities.

### 中文

#### CLI 客户端接管优化

- **Codex CLI**：创建或更新接管配置时，完整保留 `config.toml` 中 `[model_providers.clipal]` 下原有的用户自定义选项，仅更新 Clipal 专有路由字段。
- **Goose**：在生成 `custom_providers/clipal.json` 的同时，同步更新全局 `config.yaml` 中的 `active_provider: clipal` 与 `providers.clipal.model`，使新会话无需手动切换即可直接走 Clipal。
- **Goose 前置拦截**：若检测到 `GOOSE_PROVIDER` 或 `GOOSE_MODEL` 环境变量，主动拦截接管并提示取消变量覆盖，避免配置写入后未实际生效。
- **OpenCode v2 对齐**：适配 OpenCode v2 配置规范，仅对 Clipal 中已启用的基础协议供应商（OpenAI -> `/v1`、Anthropic -> `/`、Google -> `/`）重定向端点，不篡改本地模型列表，保持 models.dev 目录与会话选择的原生体验。
- **OpenCode 策略与覆盖检测**：支持 OpenCode 原生通配符策略检查，遇 `provider.use` 拒绝策略时安全中止；检测多层配置文件间可能存在的端点遮蔽冲突。
- **遗留特征识别精准化**：严格匹配 `/clipal` 与 `/clipal/v1` 确切网关路径，杜绝类似 `/clipal-proxy` 等第三方同名地址的误判。

#### 独立安装脚本

- **PowerShell (`install.ps1`)**：改用 `releases/latest` 的 HTTP 302 重定向头解析最新版本，彻底摆脱对 GitHub REST API 的依赖，规避局域网/共享 IP 下 60 次/小时的调用频次限制。

#### 文档更新

- 在客户端配置手册中补充了 Goose 环境变量优先级说明与 Grok 多层配置覆盖判定规则。
