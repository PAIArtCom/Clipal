## v0.30.0

### English

#### Highlights

- OAuth accounts now have explicit request environment profiles covering confirmed region, language, locale, timezone, DNS policy and derived request headers.
- Every OAuth provider attempt binds the selected account identity, refreshed credential, effective request environment and transport generation together. Provider failover therefore applies the selected account's environment instead of carrying the previous account's settings.
- Added an explicit OAuth authentication probe for Codex, Claude and Antigravity. Diagnostics distinguish local request-profile configuration, target connectivity, reference observations and upstream OAuth acceptance.
- Added redacted account-attempt status for troubleshooting provider selection and environment binding without exposing tokens or account secrets.

#### Compatibility and Scope

- Existing OAuth credentials continue to load; missing request environments are normalized using the existing defaults and are persisted when the credential is next saved.
- Request environments belong to OAuth accounts and affect Clipal's provider requests only. Clipal does not manage caller processes, operating-system locale or timezone, browser state, or browser profiles.
- Authentication-probe evidence is diagnostic and is not persisted as account configuration. A successful reference observation does not prove OAuth authentication.

#### Verification

- `go test ./...` passes.
- Race-enabled OAuth, proxy and Web UI tests pass.
- The Web UI test suite passes all 159 tests.
- GolangCI-Lint and diff checks pass.
- Live multi-account Codex and Claude failover tests confirmed that usage-limited accounts switch to an available account and that the selected account's environment follows the request. Temporary test instances and copied OAuth data were removed afterward.

### 中文

#### 亮点

- OAuth 账号现在拥有明确的请求环境配置，包含已确认的地区、语言、locale、时区、DNS 策略和派生请求 header。
- 每次 OAuth Provider 尝试都会同时绑定所选账号身份、刷新后的 credential、有效请求环境和 transport generation。Provider 故障切换时会重新应用目标账号的环境，不再沿用前一个账号的设置。
- 为 Codex、Claude 和 Antigravity 增加明确的 OAuth 认证探针。诊断会区分本地请求配置、目标连接、参考出口观测和上游 OAuth 接受情况。
- 增加脱敏的账号尝试状态，便于排查 Provider 选择和环境绑定，同时不暴露 token 或账号机密。

#### 兼容性与范围

- 现有 OAuth credential 可以继续加载；缺少请求环境的旧 credential 会使用现有默认值进行规范化，并在下一次保存 credential 时持久化。
- 请求环境属于 OAuth 账号，只影响 Clipal 发出的 Provider 请求。Clipal 不管理调用方进程、操作系统语言或时区、浏览器状态或浏览器 profile。
- 认证探针证据仅用于诊断，不会作为账号配置持久化。参考出口观测成功不代表 OAuth 认证成功。

#### 验证

- `go test ./...` 通过。
- OAuth、Proxy 和 Web UI 的 race 测试通过。
- Web UI 测试套件 159 项全部通过。
- GolangCI-Lint 和 diff 检查通过。
- 多账号 Codex 与 Claude live failover 测试确认：usage limit 账号会切换到可用账号，且请求会跟随目标账号使用对应环境。测试结束后已删除临时实例和复制的 OAuth 数据。
