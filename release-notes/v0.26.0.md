## v0.26.0

### English

#### Highlights

- Redesigned the management UI with a provider list and detail inspector, clearer runtime status and request activity, and improved layouts on narrow screens.
- Added system proxy support and automatic fallback from DoH to the system hostname route, adapting to the existing network without changing its settings.
- Repaired Antigravity account initialization and made Gemini live tests discover supported models before generation.

#### What Changed

- Provider selection, dialogs, settings drafts and loading states now handle in-flight operations more consistently. Failed settings loads expose retry, while provider failures display actionable upstream details.
- Inherited routing reads environment and system proxy settings per request. Environment variables take precedence; `ALL_PROXY` and `NO_PROXY` are supported. Explicit direct and custom proxy choices remain authoritative, and failed proxy connections never silently switch to direct connections.
- System proxy support includes native macOS settings and PAC, Windows WinHTTP settings, and manual GNOME settings on Linux. Non-CGO macOS builds support static settings; GNOME PAC requires a supported external proxy route and is reported unsupported. Other Linux desktops can use proxy environment variables.
- Without a selected proxy, automatic DNS tries Cloudflare → Google DoH first, then the system hostname route if lookup or connection establishment fails. Connection attempts have bounded budgets and retain original-domain TLS verification. Business requests are not replayed. Explicit Cloudflare/Google DNS policies remain strict.
- DoH answers are cached per account/route and normalized hostname, using the earliest response expiry and a five-minute cap. Concurrent queries are coalesced, failures back off for five seconds, and cache entries are bounded. Returned addresses are isolated from caller mutation; waiter cancellation does not cancel another caller's lookup.
- Antigravity credentials missing a project can be repaired through the account initialization flow. Rotated tokens retain verified account identity, and account eligibility, validation and user-provided project requirements produce explicit setup errors instead of fabricated project identifiers.
- Gemini live tests fetch the model catalog, select compatible text models dynamically, and validate ordinary and SSE output with terminal `STOP`. Installed-service tests can temporarily select a provider and restore routing afterward. Bash 3.2 optional arguments and local-service requests under proxy settings have regression coverage.

#### Compatibility

- Existing account region, timezone and DNS choices are preserved. No operating-system DNS, proxy, VPN or TUN settings are modified.
- No manual configuration migration is required. Accounts requiring upstream validation or a user-provided Google Cloud project still need to satisfy those requirements.

### 中文

#### 亮点

- 管理界面采用 provider 列表与详情面板，优化运行状态、请求活动展示及窄屏布局。
- 新增系统代理支持，DoH 失败后自动回退系统域名通路，适配已有网络而不修改网络设置。
- 修复 Antigravity 账号初始化，Gemini 真实测试先获取支持模型列表，再动态选模。

#### 变更内容

- provider 选择、对话框、设置草稿及加载状态更一致地处理进行中的操作。设置加载失败后可重试，provider 异常展示上游错误详情。
- 继承模式按请求读取环境变量和系统代理，环境变量优先，支持 `ALL_PROXY` 与 `NO_PROXY`。显式直连及自定义代理仍具有优先权；代理连接失败不会静默切换直连。
- 系统代理支持 macOS 原生设置及 PAC、Windows WinHTTP 设置、Linux GNOME 手动代理。macOS 非 CGO 构建支持静态设置；GNOME PAC 会明确报告不支持，需通过受支持的外部代理通路访问。其他 Linux 桌面可使用代理环境变量。
- 未选择代理时，自动 DNS 优先尝试 Cloudflare → Google DoH，解析或连接建立失败后回退系统域名通路。连接尝试使用有限预算，保留原始域名 TLS 校验，不重放业务请求。显式 Cloudflare／Google DNS 策略保持严格。
- DoH 缓存按账号、路由及规范化域名隔离，采用最早响应过期时间，上限五分钟；并发查询合并，失败退避五秒，缓存条目有数量上限。返回地址与缓存隔离，单个等待者取消不影响其他请求。
- 缺少 project 的 Antigravity 凭据可通过账号初始化流程修复。token 轮换保留已核验身份；账号资格、验证及用户自有项目要求返回明确初始化错误，不伪造项目标识。
- Gemini 真实测试获取模型列表后动态选择兼容文本模型，校验普通及 SSE 输出与终止 `STOP`。已运行服务的测试支持临时指定 provider 并恢复路由，补齐 Bash 3.2 可选参数及代理环境下访问本地服务的回归测试。

#### 兼容性

- 保留已有账号地区、时区及 DNS 选择，不修改操作系统 DNS、代理、VPN 或 TUN 设置。
- 无需手动迁移配置。上游要求账号验证或用户自有 Google Cloud 项目时，仍需满足相应条件。
