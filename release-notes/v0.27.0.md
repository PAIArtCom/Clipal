## v0.27.0

### English

#### Highlights

- Unified takeover and rollback for Codex CLI, Claude Code, Antigravity CLI, OpenCode, Continue, Aider, and Goose, with reusable configuration previews and recovery behavior.
- Renamed the Google provider channel from Gemini to Google, with migration for existing configuration and compatibility aliases for existing API paths.
- Added Antigravity CLI setup and takeover, repaired Gemini API requests through Antigravity OAuth, and improved subscription quota display.
- Kept provider details visible while browsing long account lists, including long details, narrow screens, and tooltips.

#### What Changed

- Takeover preserves unrelated user settings, file permissions, and symbolic links. Repeated apply keeps the original baseline for the active cycle; rollback restores that baseline, and a later cycle captures intervening user edits. Failed writes attempt to restore the previous files and retain a recovery baseline if recovery fails.
- Client configuration targets can be selected where supported, including custom files/directories, Codex profiles, and Antigravity shell startup files. Previews cover managed files, and status separates configuration inspection from runtime verification. A malformed client file no longer prevents inspecting other clients or accessing available backups.
- OpenCode inspects known merged user configuration layers before applying takeover. Provider restrictions and later routing overrides produce conflicts without modifying the restricting layers. Explicit model selection updates the actual request model ID while preserving model metadata; inferred selections retain existing aliases. Read-only planning inputs are checked again before writing.
- Continue retains custom model options and roles. Aider retains unrelated settings and auxiliary model choices. Goose retains custom provider metadata. Models requiring an explicit gateway choice are requested from the user rather than supplied as a fixed default.
- Antigravity model aliases are resolved from the account's model catalog when required, without inventing versioned model names. Quota presentation uses upstream groups and buckets and labels usage percentages consistently.
- Linux GNOME proxy inspection uses fixed executable and schema arguments, with regression coverage for HTTP/HTTPS selection and SOCKS fallback.

#### Compatibility and Upgrade Notes

- `google.yaml` is the canonical Google channel file. Existing `gemini.yaml` is renamed on load without changing its contents or permissions. Equivalent duplicate files are consolidated; differing files produce a conflict and remain untouched. Existing `gemini` channel API aliases and `/gemini` proxy paths remain accepted. Usage history and imported data normalize to `google`.
- Legacy Gemini CLI setup, takeover, and Gemini CLI OAuth support have been removed. Retired `oauth_provider: gemini` entries are excluded when loading configuration; credential files remain on disk. Gemini API key providers and Antigravity OAuth remain supported under Google. Existing Gemini CLI takeover files are not automatically restored by the new Antigravity integration.
- Restart clients or open a fresh terminal after takeover or rollback. Project, command-line, remote, managed, and process-environment overrides still require verification in the client's actual launch context. Existing Aider auxiliary models may continue using their original providers.
- Isolated live tests verified requests and rollback with Codex CLI, Antigravity CLI, OpenCode, Continue, Aider, and Goose. OpenCode 1.19.3 additionally passed explicit-alias and merged-restriction checks. Claude Code configuration and recovery have regression coverage; live upstream validation was waived because no working account was available. These checks do not establish support for every tool call or long-session scenario.

### 中文

#### 亮点

- 统一 Codex CLI、Claude Code、Antigravity CLI、OpenCode、Continue、Aider 和 Goose 的接管及回滚流程，复用配置预览与失败恢复机制。
- 将 Gemini 渠道统一命名为 Google，迁移已有配置，并兼容旧 API 路径。
- 新增 Antigravity CLI 安装引导与接管，修复 Gemini API 到 Antigravity OAuth 的请求适配，改进订阅额度展示。
- 浏览长账号列表时保持 provider 详情可见，兼容长详情、窄屏和 tooltip。

#### 变更内容

- 接管保留无关用户配置、文件权限及符号链接。重复 apply 保留当前周期的初始基线；rollback 恢复该基线，下一周期重新捕获用户在两轮之间的修改。写入失败会尝试恢复操作前文件；恢复失败时保留基线供重试。
- 按客户端能力支持选择配置文件、目录、Codex profile 和 Antigravity shell 启动文件。预览覆盖管理文件，状态区分配置检查与运行时验证。单个客户端文件损坏不再阻断其他客户端检查或已有备份的恢复入口。
- OpenCode 接管前合并已知用户配置层，发现 provider 限制或后续路由覆盖时报告冲突，不改写限制来源。显式选择模型会更新实际请求模型 ID 并保留元数据；沿用已有选择时保留别名。写入前再次检查只读配置来源是否变化。
- Continue 保留自定义模型选项与角色，Aider 保留无关配置和辅助模型选择，Goose 保留自定义 provider 元数据。需要明确网关模型时由用户选择，不填入固定默认模型。
- Antigravity 按需从账号模型目录解析别名，不拼造带版本号的模型名。额度展示使用上游分组与配额桶，统一百分比的已用语义。
- Linux GNOME 代理检查使用固定可执行文件及 schema 参数，补齐 HTTP／HTTPS 选择与 SOCKS 回退回归测试。

#### 兼容性与升级说明

- Google 渠道使用 `google.yaml`。加载时会将已有 `gemini.yaml` 重命名，保留内容和权限；两份配置等价时合并为新文件，内容不同时报告冲突并保留原文件。继续接受旧 `gemini` 渠道 API 标识及 `/gemini` 代理路径，使用统计与导入数据统一为 `google`。
- 移除旧 Gemini CLI 安装引导、接管及 Gemini CLI OAuth 支持。加载配置时排除旧 `oauth_provider: gemini` 条目，凭据文件仍保留在磁盘。Google 渠道继续支持 Gemini API Key 与 Antigravity OAuth。新的 Antigravity 接管不会自动恢复旧 Gemini CLI 接管文件。
- 接管或回滚后需重启客户端或打开新终端。项目、命令行、远程、受管及进程环境覆盖仍需在实际启动环境中验证。Aider 原有辅助模型可能继续使用原 provider。
- 隔离环境已验证 Codex CLI、Antigravity CLI、OpenCode、Continue、Aider、Goose 的真实请求与回滚；OpenCode 1.19.3 额外通过显式别名及多层限制验证。Claude Code 的配置与恢复有回归覆盖；因无可用账号，真实上游验证已获豁免。这些验证不代表覆盖所有工具调用或长会话场景。
